# ЭТАП 6: XLSX/CONF ДЛЯ КОНВЕРТЕРА ПРОТОТИПОВ

Этап 6 технически разворачивает утверждённые данные pack, сохраняя title, hint, classname, param, icon, выбранные игровые сущности и их нумерацию. Не переписывать сюжет или баланс при экспорте.

Главный технический контракт: workflows/PROTO_EXPORT_WORKFLOW.md.
Порядок работы и подробные контракты листов: workflows/WORKFLOW_GUIDE.md, раздел Stage 6.
Использовать локальный скилл .agents/skills/proto/SKILL.md.

## Перед запуском

- Все review/stage1_review.md ... stage5_review.md существуют и семантически непусты.
- Approval Stage 1–5 действуют по порядку, SHA-256 review не изменились.
- filled_tasks.validation.json и quest_group.validation.json актуальны, errors=0.
- Approval записывается только через workflow_fast.py approve, с применением review и пересборкой.

## Команды

python src/workflow_fast.py stage6 --campaign <campaign_id> --pack <pack_id>

Для уже исправленного человеком обзора:

python src/workflow_fast.py stage6-split --campaign <campaign_id> --pack <pack_id>

Существующий обзор защищён до --force-review; готовые conf-файлы — до stage6-split --force. Перезапись допустима только намеренно. Ручные правки conf обратно в обзор не переносятся.

## Результат

- review/proto/ — единственная папка конечных XLSX; отдельный многолистовой обзор не создаётся.
- review/proto/<campaign_id>_quests.xlsx, <campaign_id>_actions.xlsx, <campaign_id>_resources.xlsx, <campaign_id>_interactive_<mechanic>.xlsx — отдельные файлы, ровно один лист conf в каждом.
- review/proto/quest_<campaign_id>_accomplished.xlsx — отдельный conf, по строке на каждый quest.
- Только необходимая campaign memory; экспортные summary JSON не создаются.
- Отдельная таблица выбранной потехи, например campaigns/<campaign_id>/<pack_id>/review/proto/<campaign_id>_funcollection_4.xlsx. Её не включать в quest craft ingredients; существующие ручные правки сохранять.

Создавать только конечные XLSX/conf в review/proto/. CSV, ZIP, bundle_manifest.json, manifest.json, validation_report.json, экспортные summary JSON и дополнительный обзор не создавать. Результаты проверки выводить в консоль.

## Структура

- Quest group: ml, donor /quest_group/event/Night_2026/Night_2026_Story.proto.js, id пустой, find=Night_2026, replace=<campaign_id>. Не использовать старые extra.* и array_of_values.
- Quest N: sl, donor /quest/event/Night_2026/Night_2026_Story_N.proto.js, output /quest/event/<campaign_id>/<campaign_id>_Story_N.proto.js, id пустой при первичной генерации. Все Story и Tech квесты campaign лежат прямо в /quest/event/<campaign_id>/, без отдельных папок story_N или tech.
- Сразу после quest — по одному ml/object блоку для tasks.0, tasks.1 и т.д. Input/output обоих task указывают на новый output текущего quest. Номера в заголовках task локальны внутри quest.
- Каждый персонаж — отдельный ml блок, continuation actions без B/C и нового id. Персонажей без экшенов не пропускать.
- Каждый output с replace — отдельный блок: в sl конвертер применяет замены только для первой строки.
- Только sl/ml и поддерживаемые string/int/array/object/ignore/replace. Object и replace требуют объединений, описанных в PROTO_EXPORT_WORKFLOW.md.
- Ресурсы агрегировать по всем pack campaign; числа писать Excel-числами, id оставлять пустым. Пустой id наследует ID донора; производственные ID назначает разработчик перед импортом.

## Проверка

Открыть итоговые файлы заново, запустить validator скилла proto и src/validate_proto_exports.py с настоящим конвертером, реальными донорами и изолированным output. Проверить число output и сохранение заданных полей в JSON. Изменения кода/шаблонов проверять полным python -m unittest discover -s tests.

Пользователь проверяет эти XLSX вручную. После его сообщения о завершении закрепить подтверждённые правки в генераторах/шаблонах/документации, проверить в тестовом output/ и затем оформить скилл создания квестов. Не перезаписывать ручной эталон.
