# ЭТАП 5: СОЗДАНИЕ КВЕСТОВОЙ ГРУППЫ

Перед написанием текста quest group прочитай `docs/domovata_style_guide.md`. Все тексты `title`, `description`, `description_complete`, `description_spoil` должны соответствовать стилю Домовят.

Этап 5 выполняется после этапа 4, когда `filled_tasks.json` уже создан для текущего pack, проверен валидатором и показан пользователю.

Перед стартом этапа 5 нужен явный апрув этапа 4 в чате и technical gate:

```bash
python src/workflow_fast.py approve --stage 4 --campaign <campaign_id> --pack <pack_id>
```

Цель этапа 5: ИИ анализирует контекст всех квестов текущего pack и пишет общую квестовую группу для страницы журнала.

Входные файлы:

- `campaigns/<campaign_id>/<pack_id>/filled_tasks.json`
- `campaigns/<campaign_id>/<pack_id>/filled_tasks.validation.json`
- при необходимости `campaigns/<campaign_id>/<pack_id>/stage1_story.txt`
- при необходимости `campaigns/<campaign_id>/<pack_id>/stage2_story.txt`
- при необходимости `campaigns/<campaign_id>/<pack_id>/stage3_quests.txt`

Выходные файлы:

- `campaigns/<campaign_id>/<pack_id>/quest_group_choices.json`
- `campaigns/<campaign_id>/<pack_id>/quest_group.json`
- `campaigns/<campaign_id>/<pack_id>/quest_group.validation.json`
- `campaigns/<campaign_id>/<pack_id>/quest_group.preview.md`

`quest_group` привязан к pack, поэтому постоянным источником правды является папка pack в `campaigns/`, а не временная папка `output/`.

## Поля квестовой группы

Структура соответствует верхнему `ml`-блоку CSV:

```json
{
  "input": "/quest_group/fun/Fun13_Story_1.proto.js",
  "output": "/quest_group/fun/<CurrentQuestGroup>.proto.js",
  "title": "...",
  "description": "...",
  "description_complete": "...",
  "description_spoil": "...",
  "extra": {
    "quest_reward_prewiew": ["", "", ""],
    "description_condition": "...",
    "description_complete": "..."
  }
}
```

Правила:

- `input` всегда строго `/quest_group/fun/Fun13_Story_1.proto.js`.
- `output` строится из текущих `campaign_id` и `pack_id`: `/quest_group/fun/<campaign_id>_<pack_id>.proto.js`, например `/quest_group/fun/MeatballRain_2026_pack_002.proto.js`.
- `title` пишет ИИ по смыслу всего pack.
- `description` — краткая завязка всего pack.
- `description_complete` — краткое успешное завершение всего pack.
- `description_spoil` — краткое провальное/неуспешное завершение всего pack.
- `extra.quest_reward_prewiew` всегда содержит три пустые строки: `["", "", ""]`.
- `extra.description_condition` должно полностью совпадать с `description`.
- `extra.description_complete` должно полностью совпадать с `description_complete`.

## Как писать текст

ИИ должен смотреть на весь pack, а не только на первый квест.

Нужно учитывать:

- общую завязку;
- конфликт или странность, с которой начинается pack;
- главных персонажей;
- финальный результат последнего квеста;
- тон кампании.

Текст должен быть коротким, дружелюбным и приключенческим: не пересказывать каждый таск, а объяснять общий смысл серии.

Стиль quest group — обращение к игроку, но не формально:
- звучать как приглашение в приключение, а не как сухой отчёт;
- сохранять юмор и сказочность кампании;
- писать напрямую игроку ("Вам предстоит...", "Вы отправляетесь..."), но **не использовать** "Необходимо", "Требуется", "Миссия";
- в `description_spoil` писать мягко и чуть шутливо, что пошло не так и что стоит попробовать в следующий раз;
- избегать злобных угроз или депрессивных концовок даже в `description_spoil`;
- сохранять тёплый тон Домовят даже в провальной версии.

Пример стиля:

```text
description: Вы догоняете отважную воительницу на пути к краю света. Вместе вам предстоит перехитрить Движущийся лес, разгадать тайну Бездонной пропасти и решить, что делать, когда грозный зверь просит помощи, а не боя.
description_complete: Вы преодолели лес, раскрыли секрет пропасти и усмирили гнев тигровой виверны, вернув ей потерявшихся детёнышей. В благодарность новый друг теперь готов перенести вас к самому краю света.
description_spoil: В лесу мы заплутали, так и не нашли выход из чащи. В следующий раз нужно волшебный клубочек не забыть!
```

Нельзя:

- придумывать новые реальные игровые classname;
- менять `filled_tasks.json`;
- менять `context_pack.json`;
- запускать CSV;
- использовать `extra.quest_reward_prewiew` для наград, пока пользователь не попросит.

## CLI

После того как ИИ написал тексты, сохрани их в `campaigns/<campaign_id>/<pack_id>/quest_group_choices.json`:

```json
{
  "title": "...",
  "description": "...",
  "description_complete": "...",
  "description_spoil": "..."
}
```

Затем собрать JSON можно так:

```bash
python src/workflow_fast.py quest-group --campaign <campaign_id> --pack <pack_id>
```

Старый вариант с передачей текстов в CLI тоже поддерживается:

```bash
python src/workflow_fast.py quest-group \
  --campaign <campaign_id> \
  --pack <pack_id> \
  --title "..." \
  --description "..." \
  --description-complete "..." \
  --description-spoil "..."
```

Скрипт прочитает `campaigns/<campaign_id>/<pack_id>/filled_tasks.json` и создаст `quest_group.json`, validation и preview в той же папке pack.

Если нужно вручную взять `filled_tasks.json` из другого места, путь можно передать первым аргументом, но `quest_group` всё равно по умолчанию будет записан в `campaigns/<campaign_id>/<pack_id>/`.

После результата этапа 5 нужно остановиться, показать пользователю `quest_group.json`/preview и ждать явный апрув.

После апрува этапа 5 записать gate:

```bash
python src/workflow_fast.py approve --stage 5 --campaign <campaign_id> --pack <pack_id>
```

Без этого этап 6 / CSV должен отказаться запускаться.
